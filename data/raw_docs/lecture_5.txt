# Correlation, Arbitrary, and Cardinality
| Correlation | A statistical measure that describes the size and direction of a relationship between two variables. It tells us if two things "move together.” Positive Correlation: As X increases, Y also increases (e.g., Temperature vs. Ice Cream Sales, Years of experience vs. Salary). Negative Correlation: As X increases, Y decreases (e.g., Price of a product vs. Number of buyers). No Correlation: The movement of X has no predictable effect on Y. |
| --- | --- |
| Arbitrary | Data points (often in network chart) assigned randomly or for convenience, rather than being based on a natural scale or logical measurement. They are often used for identification or indexing purposes. Example: In network chart, The "Top" of the chart doesn't necessarily mean "High Value"—it’s just where the dot happened to be placed. |
| Cardinality | The number of unique values in a dataset. High Cardinality: A column with a high percentage of unique values. For example: GPS coordinates (latitude/longitude). Every point is likely a different number. Low Cardinality: A column with very few unique values or categories. For example: "Employment Status" (Full-time, Part-time, Unemployed). There are only 3 unique possibilities for thousands of people. Also "Gender" has low cardinality. |

---

# Overplotting, Jittering, and binning
| The "clutter" problem that happens with discrete numerical data |  |
| --- | --- |
| Overplotting Problem | Occurs when data points in a chart overlap to the extent that you can no longer distinguish individual points or see the true density of the data. This is extremely common with Low Cardinality or Discrete data. |
| Jittering (The "Shake" Method) Solution 1 | It is a data visualization technique where you add a small amount of random "noise" (slight movement) to the position of each data point. This "shakes" the dots apart so you can see every individual record without changing the overall meaning of the data. |
| Binning / Heatmaps (The "Bucket" Method) Solution 2 | Instead of drawing dots, you divide the chart into squares or hexagons. You color the square based on how many points fall inside it. |

# The Numerical Family (Quantitative)
Numerical data is always about numbers. It answers, "How many?" or "How much?”

Continuous (Measuring): Data that can be divided into smaller and smaller decimals. It has no "gaps.”. It is the data that can take any value in a range. Infinite possibilities.
Example: A person's height (1.75m, 1.755m, 1.7552m), Temperature ($22.51$°C), weight, revenue. You can always be more precise.

Discrete (Counting): Data that must be a "whole" number. You cannot have half of the item. It is the data that consists of "countable" whole numbers.
Example: The number of students in a class (25 or 26). You cannot have 25.5 students. Also, the number of children (3), number of cars.

---

# The Categorical Family (Qualitative)
Categorical data is about labels or groups. It answers, "What kind?”

Discrete (Standard Categorical): Almost all categorical data is Discrete because you belong to one "bucket" or another. There is no "in-between.”
	Ordered: Labels that follow a specific, logical sequence. Such as survey results (Poor, Good, Excellent), Seniority (Level 1, Level 2, Level 3, and Level 4).
Unordered: Labels with no inherent "ranking" or "order." such as Blood Type (A, B, AB, O), Country (Egypt, USA), Color, Department.

Continuous (Rarely used in Categories): Generally, we do not use the term "continuous" for categories.

---

| Data Family | Sub-Type | How to Identify | Example |
| --- | --- | --- | --- |
| Numerical | Continuous | Gaps and Infinite Possibilities | Price ($19.99), Weight (70.5kg) |
| Numerical | Discrete | ”Countable" Whole Numbers | Number of cars (3), Goals scored (2) |
| Categorical | Discrete | Ordered Groups | Poor, Good, Excellent |
|  |  | Unordered Groups | Eye color (Blue), Country (Egypt) |

# Scatter vs Bubble vs network
| Type | Reason for Use (Conditions) | Keywords | Variable Type (X vs Y) |
| --- | --- | --- | --- |
| Scatter | To see if one numerical variable affects another. Ideal for spotting patterns or "freak" occurrences. | Correlation, Outlier, Group, Cluster, Influence, Proportionality | Continuous vs. Continuous |
| Bubble | To compare three numerical variables at once. It adds "Weight" to see if one numerical variable affects another. | Correlation, Outlier, Group, Cluster, Influence, Proportionality + (weight or size) | Continuous vs. Continuous (plus, Discrete/Continuous for Size) |
| Network | To map how different entities are linked. It is about "Flow" and "Distance" rather than numbers on an axis. | Connectivity, Node, Path, Centrality, Hierarchy | Categorical vs. Categorical (Arbitrary Positioning) |

# How to Draw scatter and bubble chart? (our guidelines)
| Rule # | Guideline | Purpose / Description |
| --- | --- | --- |
| Rule 1 | Chart Border | Ensure a black frame surrounds the data area to define the workspace. |
| Rule 2 | Zero Baseline | The Y-axis must start at 0 to avoid distorting the magnitude of the plots. |
| Rule 3 | Horizontal/Vertical Text | All labels in the chart, such as those in the X-axis, Legends, Bottom, and Top titles, must be horizontal for easy reading, except the Y-axis, which must be vertically oriented. |
| Rule 4 | Include Legend | Place a legend (usually top-right) to explain what the plot colors represent. |
| Rule 5 | Clear Titles | Every chart needs three titles: a Main Title, an X-axis Title, and a Y-axis Title. |
| Rule 6 | Color Strategy | In case of one cluster: use one uniform light color (e.g., lightblue) with a black border for all plots. In case of more than one cluster: use one uniform light color with a black border for each cluster (e.g., lightblue for cluster A, lightgreen for cluster B, and lightred for cluster C). In case of outliers: use one uniform light color (e.g., lightblue) with a black border for all plots and a different light color (e.g., lightgreen) for the outliers. |
| Rule 7 | Gridlines | Draw the gridlines to assist in reading the values. |
| Rule 8 | Outliers Strategy | Add the label of the outlier if it is required in the audience question. |

# Network chart
| Feature | Scatter / Bubble Charts | Network Charts |
| --- | --- | --- |
| Primary System | Coordinate System (X and Y axes) | Connectivity System (Nodes and Edges) |
| Positioning | Fixed: Based on magnitude/measurement | Arbitrary: Based on layout convenience |
| Components | Plots representing data points | Nodes (entities) and Edges (links) |
| Visual Goal | To see Correlation and Proportionality | To see Connectivity and Paths |

---

# Network chart

| The Scatter Plot (Left): If we moved that dot to the left, its Value would change. |
| --- |
| The Network Chart (Right): If we moved 'Node X' to the top of the screen, the Relationship remains exactly the same. Its position is just for visual convenience. |

---

# How to Draw network chart? (our guidelines)
| Rule # | Guideline | Purpose / Description |
| --- | --- | --- |
| Rule 1 | Chart Border | Ensure a black frame surrounds the data area to define the workspace. |
| Rule 2 | Edges | Avoid edge intersections.Write the label on/inside the edge and summarize it in case of long labels.Color all the edges using black. |
| Rule 3 | Nodes | Must have a black border. Write the label inside the node and summarize it in case of long labels.Color all the nodes using lightblue. |
| Rule 4 | Path | Use a black dashed line for the edges. Use a dashed border for all the nodes inside the path. Color all the nodes inside the path using lightgreen. |
| Rule 5 | Centrality | Color all the nodes using lightblue, except the central node; use lightgreen color. Use a dashed border for the central node. |
| Rule 6 | Include Legend | Place a legend (usually top-right) to explain what the edge/node colors represent. |
| Rule 7 | Clear Titles | Network chart needs only one title: Main Title. |
